# Radom route drafts (23 September 2026)

Two direction-specific routes are available in the **Trasa GPS** selector:

- `radom_limanowskiego_25_czerwca_draft`: Limanowskiego/Maratońska to the 25 Czerwca/Prażmowskiego roundabout. Derived from run `7aa31a9922424dc4b2d6737581cc856d`.
- `radom_25_czerwca_limanowskiego_draft`: the roundabout to Limanowskiego/Maratońska. Derived from run `fab1831c4aa2493abf6cc114cc342222`.

The initial lines in `data/routes` were generated by `python tools/build_radom_routes.py`. The builder verifies the completed recording checksums, retains moving GPS fixes, smooths them with a five-point median, and simplifies the result to a small polyline. Original recordings are not changed. The route files are then enriched by `python tools/build_radom_map.py <osm-xml>`. This second script uses the OpenStreetMap API 0.6 extract at `https://api.openstreetmap.org/api/0.6/map?bbox=21.126,51.388,21.162,51.395` (obtained 2026-09-23), writes the local street map and projects selected OSM traffic-signal nodes onto each GPS route. The source XML is not retained in the repository. Rebuilding routes requires running both scripts in order. The line follows the recorded vehicle path approximately; it is not a surveyed lane or road centreline. The first longer run (`36607e47…`) is independent validation material because its endpoint extends beyond this segment.

To inspect one, start GreenWave, choose **Nagranie GPS** (or **Telefon na żywo**), then load the corresponding run. Replay automatically selects its exact source route for these two recorded runs; other recordings require an explicit **Trasa GPS** selection. The route appears as a dashed yellow line, the recorded track is overlaid on the local OSM street background, and the candidate lines are numbered red markers. Without a selected route, only the GPS trace is shown and the map displays a notice. In **Telefon na żywo**, the right panel lists the selected route's candidate lines. A passenger can select one and record GREEN/YELLOW/RED as either **STATE_SEEN** (colour visible now, unknown phase start) or **STATE_START** (observed change at that moment). Route observations are saved as `ROUTE_OBSERVATION` events when a recording is active; they do not modify the simulation prediction or create verified phase data. The driver must not operate the controls.

Initial replay analysis: 279/289 samples matched the outbound draft route; 347/348 matched the return draft. Most of the remaining outbound samples were uncertain near close candidate segments. These are same-run checks, not independent accuracy estimates. The longer first run matches the return route for 171/366 samples; much of its remainder is off-route because it continues beyond the segment. A run played against the opposite-direction route yields reverse-direction and off-route states; route selection must therefore use the travel direction.

Each direction currently has seven candidate control points derived from OSM traffic-signal nodes. On 2026-09-23 the user confirmed that all displayed points agree with the map and the driven route, so their **point locations** are marked `DESK_CHECKED`. The underlying GPS route geometry remains `DRAFT`. The projected cross-line is not a surveyed stop line, and desktop confirmation does not prove which signal head controls a lane or movement. A conservative replay detector confirmed only 1/7 crossings outbound and 4/7 inbound; the rest remain unconfirmed because of match uncertainty or the wide position uncertainty assigned to these lines. Do not interpret an unconfirmed crossing as a red-light passage or a colour observation. A passenger must validate actual stop lines, relevant signal heads, movements, road limits and phase observations before any live speed recommendation can be enabled.
