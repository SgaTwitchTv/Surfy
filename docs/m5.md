# M5 — L09: trwałe logi przejazdów

M5 dodaje lokalny, append-only logger surowych przejazdów. Nagranie rozpoczyna
się przyciskiem „Rozpocznij nagranie”, a kończy przyciskiem, resetem, końcem
trasy, incydentem albo zamknięciem serwera. Każdy przejazd ma losowe `run_id`.

## Format

`data/runs/<run_id>/` zawiera:

- `metadata.json` — niezmienny snapshot korytarza, sesji, zegarów, predykcji,
  relacji, ustawień pojazdu, solvera, trajektorii i symulatora;
- `raw.csv` — surowe rekordy w kolejności przyjęcia z numerem `sequence`;
- `complete.json` — manifest zakończenia, liczności eventów i SHA-256 dwóch
  pierwszych plików.

CSV obejmuje timestamp UTC, czas symulacji/modelu, typ eventu, sygnalizator,
źródło, pozycję, prędkość, następny punkt i wydaną prędkość docelową. Gdy GPS
jest niedostępny, pola lokalizacji pozostają puste; współrzędne demo mapy nie są
udawane jako pomiar.

Zapisywane są `RUN_START`, `TELEMETRY` (co sekundę czasu modelu), `CONTROL`,
`RECOMMENDATION`, `GREEN_START`/`YELLOW_START`/`RED_START`, `STATE_SEEN`,
`PASS_STOP_LINE`, `INCIDENT` i `RUN_END`. Eventy są synchronizowane z tym samym
wątkiem aplikacji co symulacja. Zapis jest flushowany i synchronizowany z dyskiem
po każdym rekordzie; po błędzie logger oznacza nagranie jako przerwane i nie
udaje kompletności.

Surowy log nigdy nie jest nadpisywany. Nowe nagranie tworzy nowy katalog nawet
po resecie. Brak `complete.json` oznacza `UNFINISHED`; uszkodzony katalog jest
raportowany jako `DAMAGED`. Eksport nie naprawia ani nie normalizuje danych.

## API i UI

- `POST /api/recording` z `command=start|stop` rozpoczyna lub kończy nagranie;
- `GET /api/runs` zwraca listę zakończonych, trwających i przerwanych zapisów;
- `GET /api/runs/<run_id>.zip` wymaga lokalnego tokena i zwraca ZIP z dostępnymi
  plikami. Eksport aktywnego nagrania jest blokowany do czasu jego zakończenia.

Panel pokazuje aktywne `run_id`, liczbę rekordów, listę plików i przycisk pobrania.
Lista jest odświeżana tylko po zmianie stanu nagrania, nie przy każdym pollingu.

## Granice L09

To trwały zapis raw run, a nie pipeline analityczny. Nie modyfikujemy danych
źródłowych po przejeździe, nie uczymy jeszcze modelu i nie odtwarzamy przejazdu.
Replay, seek i rekonstrukcja stanu należą do M6. Logger nie jest bazą wieloużytkownikową
ani usługą sieciową; serwer działa wyłącznie na loopback.

Testy sprawdzają kolejność rekordów, manifest i hashe, odmowę eksportu aktywnego
pliku, status przerwanego zapisu, reset, obserwacje, API ZIP oraz zapis do końca
trasy. Dane katalogu `data/runs` pozostają lokalne i nie powinny być commitowane
do repozytorium.
