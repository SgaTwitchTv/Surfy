# M2 — obserwacje, prognozy i resynchronizacja

## Zakres wykonany

- **P02:** typowane obserwacje, UTC/symulacja, GREEN/YELLOW/RED, STATE_START/STATE_SEEN,
  sesje, historia, deduplikacja i oznaczanie późnych eventów.
- **P03:** PredictionEngine niezależny od symulatora, nominalne zielone okna,
  lokalna resynchronizacja, jawne relacje, wersja modelu i eventy aktualizacji.
- **P04:** marginesy, ich wzrost z wiekiem i horyzontem, ważność, opcjonalny indeks
  confidence, brak prognozy dla UNKNOWN/ACTUATED/ADAPTIVE, diagnostyka.
- **Uzgodnione rozszerzenie:** lokalny ekran mapy z sondą i punktami testowymi,
  połączony z tą samą warstwą obserwacji i predykcji. Pan/zoom, widok jasny/ciemny,
  obsługa wąskiego okna, diagnostyka i historia.

## Przepływ

Przycisk → lokalne API → GreenWaveApplication → ObservationService → SignalObserved
→ PredictionEngine → ModelResynchronized (jeżeli zmieniono fazy) i PredictionUpdated
→ odświeżenie mapy, listy oraz diagnostyki. Odczyt stanu jest odświeżany co 250 ms.
EventBus i rdzeń działają w jednym wątku serwera, więc obserwacja i snapshot nie
modyfikują modelu równolegle. Starszy Tkinter działa jako osobny panel P02.

Nie ma jeszcze TrajectorySolver ani rekomendacji prędkości. Nie ma trwałego logu,
replay, GPS, pobierania kafli online ani routingu A–B.

## Czas

Model testowy używa sekund symulacji. UTC obserwacji jest zachowane niezależnie
od pauzy/tempa. Dla niezweryfikowanego korytarza model używa sekund UTC od początku
sesji, ponieważ brak geometrii blokuje ruch sondy, ale nie obserwacje operatora.
Nie zamieniamy zegara przyspieszonej symulacji na rzeczywisty UTC.
Timestamp oznacza obsługę żądania przez lokalny serwer, a nie fizyczny moment
zmiany lampy. Nieznane opóźnienie operatora nie staje się zerową niepewnością.

## Resynchronizacja

- GREEN/STATE_START: offset = czas obserwacji.
- YELLOW/STATE_START: offset = czas obserwacji − znana długość zielonego.
- RED/STATE_START: offset = czas obserwacji − znane długości zielonego i żółtego.
- Dla nieznanego cyklu lub sygnalizacji zależnej od ruchu powyższe nie tworzy
  okresowego modelu. Pozostaje ostatnia obserwacja ze wskazaniem wieku.
- STATE_SEEN nie przesuwa początku cyklu. Sprzeczność z nominalnym modelem
  wstrzymuje jego okna, dopóki nowa informacja o początku fazy go nie zsynchronizuje.
- Surowa historia zachowuje spóźnione obserwacje. Aktywny model nie jest cofany
  przez starszy event. Event poprzedniej sesji nie modyfikuje nowej sesji.
- Identyczny ID/payload jest idempotentny. Sprzeczny payload dla tego samego ID
  jest odrzucany. Osobne kliknięcia mają różne ID.

Relacje są kierunkowe, jawne i jednokrokowe. Nie ma odwracania relacji ani
propagacji przechodniej. W M2 wymagają dwóch COORDINATED o znanym wspólnym cyklu.
Niezweryfikowane relacje są dopuszczone tylko jako PLACEHOLDER w danych testowych.
Nowsza bezpośrednia obserwacja punktu ma pierwszeństwo przed propagacją.

## Niepewność

Wszystkie ustawienia znajdują się w `data/prediction/*.json`.

Margines = niepewność kotwicy + wiek × dryf. Dla przyszłego okna uwzględniamy
również upływ czasu do jego końca. Przy relacji dodajemy jej margines oraz 25%
bezwzględnej rozbieżności obserwacji źródła. Ta reguła jest zachowawczą heurystyką
M2, a nie wyuczoną statystyką. Brak pomiaru dokładności kliknięcia oznacza
konfigurowalne założenie 1 s, oznaczone jako założenie w diagnostyce.

`GreenWindow.start/end` to nominalne granice fazy. `interior_start/end` to wnętrze
po odjęciu marginesów, ograniczone czasem bieżącym i ważnością modelu. Może być
puste (null). Nie stanowi gwarancji przejazdu ani przedziału o zadanym pokryciu
statystycznym. Stan przy granicy faz jest UNCERTAIN, a po wygaśnięciu UNKNOWN.

Confidence jest null, gdy SignalModel.confidence jest null. Jeżeli podano bazowy
indeks, zmniejszamy go wykładniczo z wiekiem i bezwzględnym błędem fazy. UI nazywa
go indeksem i nie pokazuje procentowej szansy przejazdu. Kalibracja na danych jest
zakresem M7. Nowa korekta ponownie ocenia indeks na podstawie aktualnego błędu.

## Diagnostyka

Pokazujemy czas modelu i UTC, wersję modelu, typ punktu, prawdę testową symulatora,
stan nominalny i ostrożny, offset, resztę błędu modulo cykl, wiek, ważność,
margines, źródło, indeks confidence, nominalne okna i ich wnętrza. Brak prognozy
ma tekstowy powód. Wyświetlamy też relacje i ostatni zestaw zmienionych punktów.
Ostatnia obserwacja jest opisana osobno z wiekiem, nigdy jako gwarantowany aktualny kolor.

## Mapa

`data/maps/warsaw.json` jest pochodnym wyciągiem OSM (ODbL); ma atrybucję,
adres źródła i datę pobrania. `scripts/build_map.py` odtwarza go z surowego XML OSM.
Mapa nie wykonuje żądań do zewnętrznego API. Rysowanie używa Web Mercator.
Odcinek demo pochodzi z połączonych segmentów jezdni w stronę południową.

Dostępny wyciąg nie obejmuje pełnego rzeczywistego S1–S5. Testowe pozycje są
normalizowane na odcinek mapy, oznaczone PLACEHOLDER i nie służą do geolokalizacji
linii zatrzymania. Nieznane współrzędne w plikach korytarzy nadal są null.

## Weryfikacja

Testy obejmują granice faz, offsety, lokalność, relacje i brak propagacji
przechodniej, pierwszeństwo obserwacji, spóźnione eventy, null, ACTUATED/ADAPTIVE,
sprzeczne STATE_SEEN, wiek, ważność, confidence, duże marginesy, błędne konfiguracje,
niezależność od jitteru, synchronizację zegarów, koniec trasy i lokalne API.
Scenariusz przeglądarkowy sprawdza mapę, kliknięcia, model, historię, jasny/ciemny
widok, wąskie okno i brak zewnętrznych żądań sieciowych.
